# GameTable.tsx modularization — mirror the server's `actions/` registry pattern

Pure structural refactor: **zero behavior change, zero wire-protocol change**. Goal: `GameTable.tsx` (1494 lines) becomes a thin composition root (~450 lines); every feature's state/logic/JSX lives in its own module under `components/game/table/`. Adding a feature later = one new hook file (+ optional component) + ~5 lines of root wiring, exactly like adding a domain to `server/src/engine/actions/`.

## 2. Shared modules

**`table/foundation.ts`** — moved verbatim from GameTable module scope, plus picker/phase/drop math made pure (currently inline):

```ts
export function findOwnCard(view: GameView, you: PlayerId | null, uid: string):
  { card: CardView; zone: Zone } | null;                       // was GameTable:81
export function onAnyBattlefield(view: GameView, uid: string): boolean;   // was :98
export function nextPhaseAction(phase: Phase): Action;         // was :546 — SET_PHASE next | NEXT_TURN
export function pickerMax(mode: PickerMode, libraryCount: number): number; // was :553 — 100/99/20/min(10,lib)/lib/min(30,lib)
export function battlefieldDrop(rect: DOMRect, x: number, y: number):
  { x: number; y: number };   // was :297-308 — % of own board, clamped 4–96 / 8–92, rounded to 0.1
```

**`table/hitTest.ts`** — `arrowTargetAt(x, y)` (was :108), DOM-dependent so kept out of foundation.

**`table/keybinds.ts`** — the registry, translating `actions/internal.ts` + `actions/index.ts` to React:

```ts
export type KeybindHandler = () => void;
export type KeybindSlice = Partial<Record<KeybindId, KeybindHandler>>;

/** Dispatcher: owns shortcutsOpen ("?" toggle), guards event.repeat /
 *  isTypingTarget / inert-while-sheet-open, preventDefaults every match. */
export function useTableKeybinds(handlers: Record<KeybindId, KeybindHandler>): {
  shortcutsOpen: boolean; closeShortcuts: () => void;
}
```

Composition happens in the root as an **annotated object literal of spreads** — the exact `index.ts` trick: a `KeybindId` added to `lib/keybinds.ts` without a handler slice fails `tsc`, and slices stay `Partial` so each feature registers only its own ids:

```ts
const keybinds: Record<KeybindId, KeybindHandler> = {
  ...game.keybinds, ...pile.keybinds, ...pickerFlow.keybinds, ...arrows.keybinds,
  ...selection.keybinds, ...chatSignals.keybinds, ...hoverActions.keybinds,
};
```

Effect subscribes with `handlers` in deps (re-subscribe cadence ≈ today's — the current effect already re-subscribes on every `view` snapshot). No latest-ref gymnastics unless lint forces it.

**`table/escape.ts`** — `useEscapeChain(chain: Array<() => boolean>)`: on Escape, run entries in order; first `true` (consumed) stops the chain; `false` entries continue. This reproduces today's priority cascade exactly: priority features return `true` only when their thing was open; catch-all features always close + return `false`, so they still all run together when no priority tier matched.

## 5. Root composition (what stays in GameTable.tsx)

Hook calls in dependency order → two composite handlers (the only cross-feature logic the root keeps, each commented):

```ts
const onCardPointerDown = (card, e) => {
  if (arrows.maybeStartFromPointer(card, e)) return;  // ctrl/⌘+RMB on any battlefield card
  if (selection.mode || arrows.picking || attach.source) return;
  drag.begin(card, e);   // begin checks button===0 + own card in battlefield/hand
};
const onCardContextMenu = (card, e) => {
  e.preventDefault();
  if (arrows.picking || arrows.draft || attach.source || e.ctrlKey || e.metaKey) return;
  menu.open(card, e.clientX, e.clientY);
};
```

Then the keybind literal, `useEscapeChain([...])` in exact current priority order (focusView.escape → reveal.escapePopup → reveal.escapeAudience → arrows.escape → attach.escape → catch-all closers from menu/picker/pile/selection/preview/header/root's `actionsOpen` + closeShortcuts), the `if (!self)` early return **after all hook calls** (as today — hooks take nullable `self`/`view`/`you`), `hand`/`libraryCount` derivations, and the JSX: `<TableHeader/>`, ZoneRail, Battlefield ×2 (spread), SelectionBar/PickingBar ×2, PhaseBar (`onNext={() => send(nextPhaseAction(view.phase))}`), HandFan, ChatPanel, overlay, CardPreview, ArrowDraft, `<DragGhost/>`, and the 12 modal mounts with their prop wiring (ContextMenu's fan-out callbacks now call `pickerFlow.*`, `arrows.start`, `attach.start`, `menu.*`, `reveal.openAudience`).

## 7. Behavior invariants (verify each survives verbatim)

Escape priority `maximized → revealPopup → audience → arrow → attach → catch-all(list at GameTable:704-719)`; Escape has **no** typing guard today. Keybinds: `event.repeat`/`isTypingTarget` inert, `?` toggles sheet, binds inert while sheet open, `preventDefault` on every match. `closePile` shuffles only own library without `highlightTop`. Tap-on-click only for own battlefield card when drag never crossed the 5px threshold. Ctrl/⌘+RMB arrow start requires `onAnyBattlefield`; pointer-down gate order select→arrow→attach. Attach highlight only own-battlefield hosts; arrow ignores self-target. Mulligan initial = `hand.length`; `pickerMax` values exact. `revealTop` audience from own library top N with `get` names. Ghost size = `cardWidthFor(focusLive, maximized)`. Root `arrow-picking`/`attach-picking` cursor classes. CounterPopover auto-closes when card leaves own zones. `untapAll` sends only for tapped cards. `addNote` dedupe/`slice(0,8)`/empty-clears. Both Battlefield mounts get identical props incl. shared `battlefieldRef`.
