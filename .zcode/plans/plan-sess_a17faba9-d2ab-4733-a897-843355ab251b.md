# Library & Zone Actions — with per-card action menus + an Actions dock

Adds the full set of common MTG table actions. Design constraints honored throughout:
**no rules enforcement** (structural + ownership validation only), and the chat **is** the game log, so every action announces itself. Your own library order is already visible to you by design — that means scry/surveil/search/"look at top N" need **no new hidden-info machinery**; the server never reveals anything it doesn't already.

Two new UI concepts per your feedback:
1. **Zone-aware card menus** — right-clicking a card shows the *game actions that card can take from where it is*, with game-action names ("Return to hand", "Put onto battlefield", "Discard", "Exile"…), not a generic zone list.
2. **Actions dock** — an "Actions" button in the header opens a panel listing **every** game action you can take, each with a one-line description of what it does (so players know what will happen before clicking).

Of the 18 requested actions, only 4 need new server actions (discard/mill are multi-card and want one log line; scry/surveil are ordering-sensitive and must be atomic). Everything else rides the existing `MOVE_CARD` with proper UI affordances.

## 1. Shared protocol — `shared/src/index.ts`

Widen `MOVE_CARD.index` and add 4 union members:

```ts
| { type: "MOVE_CARD"; uid: string; to: Zone; index?: number | "top" | "bottom" }
| { type: "DISCARD_CARDS"; uids: string[] }          // hand → graveyard, in array order
| { type: "MILL_CARDS"; count: number }              // top N of library → graveyard
| { type: "SCRY"; look: number; top: string[]; bottom: string[] }        // partition of the top `look`
| { type: "SURVEIL"; look: number; top: string[]; graveyard: string[] }  // partition of the top `look`
```

- `"top"`/`"bottom"` sentinels make library placement first-class and race-safe (a numeric index is clamped server-side, but a stale `length` from an old snapshot could land a card near-bottom instead of bottom).
- SCRY/SURVEIL semantics: `top` + `bottom`/`graveyard` must exactly partition the top `min(look, library.length)` cards, no duplicates. The "top" group stays on top of the library **in the array order given**; the other group goes to the bottom (in array order) or graveyard (in array order). Cards below the looked-at window are untouched.

## 2. Server engine — `server/src/engine/actions/`

All in `zones.ts` (zone flows; its domain map gains 4 entries — exhaustiveness enforced by `tsc`).

**`internal.ts`** — add limits `MAX_DISCARD_AT_ONCE = 30`, `MAX_LOOK = 10`, and a shared helper:

```ts
/** Validate that a[] and b[] exactly partition (as sets, no dups) the top
 *  `look` cards of `library`; remove those cards and return them in their
 *  original top-down order, or an error. */
export function takeTopPartition(library, look, a, b):
  { ok: true; cards: CardInstance[] } | { ok: false; error: string }
```

**`zones.ts` handlers** (each: `requireStarted`, ownership via `ownCard`, then a `systemMessage` log):

| Handler | Validation (structural only) | Effect | Chat line |
|---|---|---|---|
| `drawCards` (existing) | unchanged | unchanged | **+** `Ada draws 3` (was silent) |
| `moveCard` (existing) | index: integer ≥ 0 **or** `"top"`/`"bottom"` | `"top"`→0, `"bottom"`→end | **+** `Ada moves a card from graveyard to hand` on every cross-zone move (same-zone reorder stays silent; library target says `…to top of library` / `…to bottom of library`) |
| `discardCards` | 1–30 uids; each must be actor's card **in hand** | move all to graveyard in array order, clear `attachedTo` | `Ada discards 2` |
| `millCards` | integer count 1–100 | shift top `min(count, len)` → push to graveyard | `Ada mills 3` |
| `scry` | look 1–10; partition check via `takeTopPartition` | reinsert `top` group at index 0 in array order; push `bottom` group to end in array order | `Ada scries 2 (1 on top, 1 on bottom)` |
| `surveil` | same partition check | `top` group to top; `graveyard` group pushed to graveyard in array order | `Ada surveils 3 (1 on top, 2 to graveyard)` |

For `moveCard` logging, detect the source zone before `removeFromZone` (loop `Object.entries(actor.zones)` for the list containing the card).

**Tests — `zones.test.ts` additions** (existing `setup/startWithDeck/act/mustOk/mustFail/uidAt` harness):
- discard: happy path (hand → graveyard in order), non-hand uid rejected, other player's card rejected, >30 rejected, log asserted.
- mill: exact count, over-mill clamps at library size, library below N untouched, log asserted.
- scry: partition lands exactly (assert order via `uidAt`), library smaller than `look`, duplicate uid rejected, uid from below the top-`look` window rejected, missing/extra uid rejected, log asserted.
- surveil: same matrix + graveyard order.
- moveCard: `"top"`/`"bottom"` sentinels, log on cross-zone move, silent on same-zone move.

## 3. Frontend — `frontend/src/components/game/`

```
game/ActionsModal.tsx       NEW  — the Actions dock (header button opens it)
game/CountPickerModal.tsx   NEW  — N picker modal
game/ScryModal.tsx          NEW  — scry/surveil arranger
game/ContextMenu.tsx        MOD  — zone-aware per-card game actions
game/PileModal.tsx          MOD  — top/bottom buttons, player-name titles, card right-click, library footer
game/HandFan.tsx            MOD  — multi-select mode

game/Battlefield.tsx        MOD  — thread onOpponentPile callback
game/PlayerBand.tsx         MOD  — opponent pile chips (grave/exile/command counts)
```

**`ContextMenu.tsx` — zone-aware card actions.** `MenuState` card kind gains `zone: Zone` (replaces `onBattlefield`) and `name: string` (GameTable resolves `getDef(card.cardId)?.name` at open time — this also fixes an existing bug where "Reveal to table" sends `annotations[0] ?? "Card"` as the name). Menu layout per card:

- Top: the 2–3 **most common game actions for that card's zone**, e.g.
  - hand: `Discard` · `Put onto battlefield`
  - battlefield: `Return to hand` · `Put into graveyard` · `Exile` (below the existing Tap / face-down / Counters / note / detach items)
  - graveyard: `Return to hand` · `Put onto battlefield` · `Exile`
  - exile: `Return to hand` · `Put onto battlefield`
  - command: `Put onto battlefield` · `Return to hand`
  - library (inside the viewer): `Draw this card` · `Put on bottom`
- Then a `Move to…` expander (same pattern as the existing Counters expander) listing **all remaining destinations with game-action labels** — `Return to hand`, `Put onto battlefield`, `Put into graveyard`, `Put into exile`, `Put into command zone`, `Put on top of library`, `Put on bottom of library`, `Move to sideboard` — hiding the card's current zone. Library top/bottom send `MOVE_CARD` with `index: "top"` / `"bottom"`.
- Then `Reveal to table` (existing, now with the correct name) and the existing card ops (tap/face-down/counters/notes/detach stay where they apply).

Quick actions send `MOVE_CARD`/`DISCARD_CARDS` directly — one click, and the chat log confirms what happened.

**Library pile right-click menu** stays lean: `Draw 1` · `Draw N…` · `View library…` · `Shuffle` (the N-actions live in the dock, avoiding duplication).

**`ActionsModal.tsx`** (new) — opened by an "Actions" header button (lucide icon, e.g. `Sparkles`), standard modal shell (copy the `TokenModal` click-away pattern). A grid of action tiles, each with an icon, name, and **one-line description**:

- *Library* — `Draw…` ("draw N cards from the top"), `Mill…` ("put the top N cards into your graveyard"), `Scry…` ("look at the top N, then sort them top/bottom"), `Surveil…` ("look at the top N, then sort them top/graveyard"), `Look at top N…` ("peek at the top of your library"), `Reveal top N…` ("show the top N to the table"), `Shuffle`, `Search library…` ("view and filter your whole library").
- *Hand* — `Select cards…` ("mark cards, then discard / exile / reveal / bottom them together") → enters the multi-select mode.

Tiles either fire immediately (Shuffle) or open the relevant picker/scry/viewer modal. A footer hint: "right-click any card for that card's actions". (Life, dice, and Next turn already live in the chat panel and are not duplicated.)

**`CountPickerModal.tsx`** (new) — props `{ title, blurb, max, confirmLabel, onConfirm(n), onClose }`. Stepper `−` / number input / `+`, clamped 1..max, Enter confirms. Used by Draw N (max 100), Mill N (max 100), Scry N (max 10), Surveil N (max 10), Look at top N (max = library size), Reveal top N (max 30).

**`ScryModal.tsx`** (new) — props `{ mode: "scry" | "surveil", cards: CardView[], getDef, send, onClose }`. Cards shown left→right = top→bottom of library. Per card: ◀ ▶ arrows to reorder within the strip, and a segmented `[Top] [Bottom]` (scry) or `[Top] [Graveyard]` (surveil) control. Live summary + confirm button state the outcome explicitly ("Scry 3 — 1 on top, 2 on bottom"). Confirm sends the atomic action; cancel sends nothing (looking is free — your library is visible only to you).

**`PileModal.tsx`** — add `playerName?: string` (title `Bob — Graveyard`), `highlightTop?: number` (dims cards beyond the top N — the "look at top N" surface), and wire `onCardContextMenu` on cards so right-clicking inside any pile opens the same zone-aware ContextMenu (GameTable's handler already refuses non-owned cards, so opponent piles get no menu). Card hover buttons gain "on bottom of library" (gated like the existing top button). Library footer gains `Draw 1` and `Shuffle` (shuffle = the natural end of a search). Opponent piles open with `canAct={false}` — read-only viewing already works.

**`HandFan.tsx`** — props add `selectMode: boolean`, `selected: Set<string>`, `onToggleSelect(card)`. A small "Select" chip sits at the top-right of the hand strip (also entered via the dock's `Select cards…`). In select mode: dragging is suppressed, clicking toggles an emerald selection ring, and GameTable renders an action bar above the strip: **Discard N · Exile N · Reveal N · To bottom N · Clear** (Discard = one `DISCARD_CARDS`; Exile/Bottom = per-card `MOVE_CARD`; Reveal = one `REVEAL_CARDS` with names from `getDef`). Any action exits select mode.

**`GameTable.tsx`** — new state: `actionsOpen`, `picker: { mode: PickerMode; max: number } | null`, `scryMode: "scry" | "surveil" | null`, `selectMode`, `selected`; `pile` widens from `Zone | null` to `{ zone: Zone; playerId?: PlayerId; highlightTop?: number } | null`. Escape chain updated: maximized → menu → dock/picker/scry → pile → select mode → token → zoom → host → focus. Library left-click **stays Draw 1**; "View library…" opens the pile modal.

**`PlayerBand.tsx` / `Battlefield.tsx`** — opponent band headers get tiny icon+count chips for Graveyard / Exile / Command (data already in `PlayerView.zones`). Click → `onOpponentPile(playerId, zone)` threaded through Battlefield → GameTable opens a read-only PileModal ("Look at" for opponents' public piles). Card-art prefetch already covers opponents' public zones and your library — no `cardIds` memo change needed.

`ChatLog.tsx`, view model, wire messages: **no changes** (all new log lines are `system` text; `ZoneView`/`CardView` untouched; cardCache version NOT bumped).

|---|---|---|---|
| Draw N | — (library: `Draw this card` per card) | `Draw…` | library pile click = Draw 1; library menu Draw 1 / Draw N… |
| Discard N | hand: `Discard` (single) | via `Select cards…` → Discard N | hand multi-select bar |
| Mill N | — | `Mill…` | — |
| Scry N | — | `Scry…` | — |
| Surveil N | — | `Surveil…` | — |
| Exile | battlefield/hand/graveyard quick action; all zones in `Move to…` | — | drag onto Exile rail pile |
| Return to hand | quick action from battlefield/graveyard/exile/command | — | drag onto hand |
| Put on top / bottom of library | `Move to…` entries (+ graveyard quick row in PileModal buttons) | — | PileModal buttons |
| Shuffle | — | `Shuffle` | library menu, viewer footer |
| Search library | per-card moves inside the viewer | `Search library…` | library menu `View library…` |
| Reveal card/group | every card menu | `Reveal top N…` | PileModal button; hand multi-select Reveal N |
| Look at / Look at top N | — | `Look at top N…` | own piles always viewable; opponent band chips |
| Put onto battlefield | quick action from hand/graveyard/exile/command | — | drag |
| Put into graveyard / command zone | `Move to…` (graveyard also battlefield quick action) | — | drag onto rail piles |
| Move to another zone | `Move to…` lists everything | — | drag |
