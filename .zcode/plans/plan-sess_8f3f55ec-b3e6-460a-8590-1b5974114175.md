# Resizable hover preview + reveal popups with hoverable chat names & targeted reveals

Three capabilities, all following existing patterns (modal idiom, `mtg:` localStorage keys, prop-drilling through `GameTable`, render-derived state instead of effects):

1. **Preview resize** — persisted per-user width (header slider popover **and** Ctrl/⌘+scroll while a preview is showing), applied to every preview surface.
2. **Reveal popup** — new `kind: "reveal"` chat entries pop up as a modal for their audience (everyone by default), dismissed by click/Esc; card names in the chat line are hoverable to show the preview again.
3. **Targeted reveals** — optional "reveal only to certain players": server filters the reveal chat entry per viewer.

## 2. GameTable wiring

- `const [previewWidth, setPreviewWidth] = useState(loadPreviewWidth);` — lazy init is safe: GameTable only mounts client-side after a WS snapshot, so no SSR hydration mismatch and no `set-state-in-effect` violation. One `useEffect(() => savePreviewWidth(previewWidth), [previewWidth])` persists changes (writes the loaded value back once — harmless normalization).
- Replace the fixed zoom block (`GameTable.tsx:677-683`) with `<CardPreview def={zoom} width={previewWidth} className="fixed bottom-[160px] left-[100px] z-50" />`.
- **Header popover** (chosen): `previewMenuOpen` state; icon-only button (`ZoomIn` from lucide, title/aria "Card preview size") next to "Actions"; dropdown cloned from the host-menu pattern (absolute panel, outside-`pointerdown` close, added to the Escape chain): label, `<input type="range" min={140} max={448} step={8}>`, live px readout, Reset (224), hint "ctrl/⌘ + scroll over a hovered card also resizes".
- **Ctrl/⌘ + wheel**:
```ts
useEffect(() => {
  function onWheel(event: WheelEvent) {
    if (!(event.ctrlKey || event.metaKey)) return; // plain scroll / trackpad pan untouched
    if (!zoom) return;                             // only while a preview is showing
    event.preventDefault();                        // block browser pinch-zoom just then
    setPreviewWidth((w) => clampPreviewWidth(w + (event.deltaY < 0 ? 16 : -16)));
  }
  window.addEventListener("wheel", onWheel, { passive: false });
  return () => window.removeEventListener("wheel", onWheel);
}, [zoom]);
```
- Pass `previewWidth` to `PileModal` (its internal zoom block at `PileModal.tsx:261-266` becomes `<CardPreview … className="absolute left-4 top-16 z-10" />`) and to `ChatPanel` → `ChatLog`.

## 3. Reveal popup + chat hover (frontend)

**`RevealPopup.tsx`** (new) — standard modal idiom (`fixed inset-0 z-40 bg-black/70` overlay + `.overlay-in` panel, click-outside and ✕ close). Props: `{ message, revealerName, isYou, isTargeted, targetNames, getDef, previewWidth, onClose }`. Header (Eye icon): "Ada revealed 3 cards" / "Ada revealed to you:" when you're a target / "You revealed to Bob:" for your own targeted reveal. Body: `flex flex-wrap gap-2 overflow-y-auto` of card images at `previewWidth` (name-labeled `aspect-[146/204]` placeholder while a def is still fetching). Footer hint: "hover the card names in chat to see them again". Render it **after** the other modals in the tree so it stacks above an open PileModal (both z-40).

**Popup trigger — render-derived, zero effects** (avoids the error-level `react-hooks/set-state-in-effect`):
```tsx
const chatBaseline = useRef<Set<string> | null>(null);
if (chatBaseline.current === null) chatBaseline.current = new Set(view.chat.map((m) => m.id));
const [dismissedReveals, setDismissedReveals] = useState<Set<string>>(() => new Set());
const revealPopup = view.chat.find((m): m is Extract<ChatMessage, { kind: "reveal" }> =>
  m.kind === "reveal" && !chatBaseline.current!.has(m.id) && !dismissedReveals.has(m.id)) ?? null;
```
Baseline seeded on mount → refresh/rejoin never replays history; dismissing adds the id and the next queued reveal (if any) shows. Because the server now filters targeted reveals per viewer (below), the popup audience falls out naturally. Escape chain gets `if (revealPopup) { dismiss; return; }` right after the `maximized` check.

**ChatLog** — new props `you`, `getDef`, `previewWidth` (threaded GameTable → ChatPanel → ChatLog). Reveal line changes:
- Names render as spans: `className="cursor-help text-emerald-300 underline decoration-dotted underline-offset-2"`, `onMouseEnter` → local `{ def, top }` state (from `getDef(c.cardId)` + `getBoundingClientRect().top`), `onMouseLeave` → clear.
- Preview renders `<CardPreview>` `fixed z-50` at `right: 296px` (280px rail + gap + padding), `top: Math.max(8, Math.min(top, innerHeight - previewWidth * CARD_RATIO - 16))` — fixed escapes the chat's `overflow-y-auto` since no ancestor uses transform/filter.
- Phrasing: broadcast stays "Ada revealed:"; targeted → "Ada revealed to you:" when `you` is in `to`; own message → "You revealed to Bob, Cal:" (target names resolved from `players`, tinted with the exported `nameColor`).

## 4. Targeted reveals (protocol + server)

**`shared/src/index.ts`** — both optional, fully backward compatible:
```ts
| { type: "REVEAL_CARDS"; cards: { uid: string; name: string }[]; to?: PlayerId[] }
| (ChatBase & { kind: "reveal"; cards: { name: string; cardId: string }[]; to?: PlayerId[] })
```
`to` absent = whole table; present = message visible only to those players **and the revealer**.

**`server/src/engine/actions/chat.ts`** `revealCards` — when `to` is defined: reject empty, dedupe, and require every id to be a seated player other than the actor (`err("unknown reveal target")` — structural like card ownership, and strict so a stale id can never silently fall back to broadcasting). Persist `to` on the message.

**`server/src/engine/view.ts`** — chat becomes viewer-filtered (first time; today it passes through whole):
```ts
chat: game.chat.filter((m) => !m.to || m.playerId === viewerId || m.to.includes(viewerId)),
```

**Entry points** — quick everyone-reveal stays one click everywhere (memory: quick actions stay quick); "Reveal to…" opens the picker:
1. **ContextMenu**: new prop `onRevealTo(card, name)`; MenuItem "Reveal to…" directly under the existing "Reveal to table" (`ContextMenu.tsx:288-294`).
2. **Hand select bar**: GroupButton "Reveal to…" next to "Reveal" (`GameTable.tsx:620-635`).
3. **PileModal**: new prop `onRevealTo(cards)`; "Reveal to…" button in the bulk-select bar. Per-card hover Eye button stays reveal-to-everyone.
4. **Actions modal "Reveal top N…"**: `confirmPicker`'s `revealTop` branch now collects the top N and opens the picker instead of sending (chained pickers already precedented by scry).

**`AudiencePickerModal.tsx`** (new, ~CountPickerModal scale: `max-w-sm`, `.overlay-in`, Esc/overlay-click cancel): "Everyone" row (default, clears selection) + checkbox row per other seated player (multi-select, name-colored, disabled when offline is fine to skip). Confirm → `onConfirm(targets.length ? targets : null)`.

**GameTable**: `const [audience, setAudience] = useState<{ cards: { uid: string; name: string }[] } | null>(null);` — confirm sends `REVEAL_CARDS` (+`to` when picked). Escape chain order: maximized → revealPopup → audience → existing sequence … → previewMenu.

## Acceptance criteria

- Slider popover and Ctrl/⌘+scroll both resize the hover preview live (16px steps, 140–448); width persists across reloads and applies to table/hand hover, PileModal zoom, chat mentions, and reveal popup cards. Ctrl+scroll with no preview showing still zooms the browser.
- Any reveal (hand select, top-N, pile viewer, context menu) pops a card-image modal for its audience — including the revealer — dismissed by click or Esc; stacking above an open PileModal works, Escape closes the popup first. Refresh/rejoin replays nothing.
- Chat reveal lines show dotted-underlined card names; hovering shows the preview left of the chat rail, clamped to the viewport.
- Targeted reveals: only target(s) + revealer see the chat line and popup; others see nothing; stale/self/empty target ids are rejected server-side.
- `npm test` green (new server tests included); `npx tsc --noEmit` + `npx eslint src` green in both `frontend/` and `server/`.
