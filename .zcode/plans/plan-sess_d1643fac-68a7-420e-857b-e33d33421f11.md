# Keyboard Shortcuts (Cockatrice defaults) + Ctrl+Right-Click Arrow Drawing

All changes are **frontend-only** — no wire protocol, shared type, or server changes. Decisions made where questions went unanswered (all easy to change later): card-level binds act on the **hovered card**; browser-reserved keys are **remapped** (Ctrl+T→Ctrl+Alt+T, Ctrl+W→Ctrl+Alt+W, F12/F11→Ctrl+Alt+=/−); arrows are **click-to-place**; keybinds are **fixed defaults** (no rebind UI yet, but structured so one can be added).

## 1. Keybind map (Cockatrice's defaults, from `shortcuts_settings.h`)

| Key | Action | Implementation (existing pieces) | Cockatrice action |
|---|---|---|---|
| `Ctrl+D` | Draw 1 | `send DRAW_CARDS {count:1}` | aDrawCard |
| `Ctrl+E` | Draw N… | `setPicker("draw")` | aDrawCards |
| `Ctrl+Enter` | Next turn | `send NEXT_TURN` | aNextTurn |
| `Ctrl+U` | Untap all my tapped permanents | loop `SET_TAPPED {value:false}` over own battlefield | aUntapAll |
| `Ctrl+S` | Shuffle library | `send SHUFFLE_LIBRARY` | aShuffle |
| `Ctrl+I` | Roll d20 | `send ROLL_DIE {sides:20}` (Cockatrice opens a dialog; we roll d20 directly — documented simplification) | aRollDie |
| `Alt+Y` | Mill 1 | `send MILL_CARDS {count:1}` | aMoveTopCardToGraveyard |
| `Alt+M` | Mill N… | `setPicker("mill")` | aMoveTopCardsToGraveyard |
| `Ctrl+Y` | Play top card onto battlefield | `MOVE_CARD {uid: self.zones.library.cards[0], to:"battlefield"}` (own library is `kind:"cards"`, index 0 = top — same fact `confirmPicker` relies on) | aMoveTopToPlay |
| `F3` / `F4` / `Ctrl+F3` | View library / graveyard / sideboard | `setPile({zone})` (note: closing the library viewer auto-shuffles — existing behavior) | aViewLibrary / aViewGraveyard / aViewSideboard |
| `Ctrl+Alt+W` ⚠ | Look at top N… | `setPicker("lookTop")` | aViewTopCards (`Ctrl+W` — browsers close the tab, un-interceptable) |
| `Ctrl+Alt+T` ⚠ | Create token… | `setTokenOpen(true)` | aCreateToken (`Ctrl+T` — new tab, un-interceptable) |
| `Ctrl+G` | Create another token | resend last `CREATE_TOKEN` args (GameTable remembers the last token created this session) | aCreateAnotherToken |
| `Ctrl+R` | Remove my arrows | `send CLEAR_ARROWS {playerId: you}` (interceptable, `preventDefault` stops refresh) | aRemoveLocalArrows |
| `Ctrl+L` | Set life | focus the life editor in ChatPanel | aSet |
| `Ctrl+Alt+=` / `Ctrl+Alt+−` ⚠ | Life +1 / −1 | `send SET_LIFE {life: life±1}` | aInc F12 / aDec F11 (F12=devtools, F11=fullscreen) |
| `Shift+Enter` | Focus chat input | focus ChatInput's `<input>` | aFocusChat |
| `Ctrl+A` | Select all hand cards | enter select mode + select all hand uids | aSelectAll |

**Hovered-card binds** (act on the card under the cursor; no-op if none / not yours):

| Key | Action | Implementation | Cockatrice action |
|---|---|---|---|
| `Alt+A` | Draw arrow from hovered card | enter arrow-picking mode (§3) | aDrawArrow |
| `Alt+F` | Turn face down/up | `SET_FACE_DOWN {value: !faceDown}` | aFlip |
| `Ctrl+Delete` | Move to graveyard | `MOVE_CARD {to:"graveyard"}` | aMoveToGraveyard |
| `Ctrl+B` | Move to bottom of library | `MOVE_CARD {to:"library", index:"bottom"}` | aMoveToBottomLibrary |
| `Alt+N` | Add note… | reuse `GameTable.addNote(card)` | aSetAnnotation |

Skipped as N/A: phase keys (Tab/Ctrl+Space — no phases), concede F2 / leave Ctrl+Q (host END_GAME ≠ concede), undo draw Ctrl+Shift+D, mulligan Ctrl+M, clone Ctrl+J, attach/unattach (drag + menu exist), tap (Cockatrice leaves aTap unbound; left-click tap stays). `Escape` keeps its existing cascade.

## 2. New file `frontend/src/lib/keybinds.ts` (+ `keybinds.test.ts`)

```ts
export type KeybindId =
  | "drawOne" | "drawMany" | "nextTurn" | "untapAll" | "shuffleLibrary" | "rollDie"
  | "millOne" | "millMany" | "playTopCard" | "viewLibrary" | "viewGraveyard"
  | "viewSideboard" | "viewTopCards" | "createToken" | "createAnotherToken"
  | "removeMyArrows" | "lifeSet" | "lifeInc" | "lifeDec" | "focusChat"
  | "selectAll" | "arrowFromHover" | "flipHover" | "graveyardHover"
  | "bottomHover" | "noteHover";

/** combo = "Ctrl+D" | "Ctrl+Enter" | "Alt+F" | "F3" | "Ctrl+Delete" | "Ctrl+Alt+T" | … */
export const DEFAULT_KEYBINDS: Record<KeybindId, string>;

/** Normalizes a KeyboardEvent to a combo string; metaKey counts as Ctrl (⌘);
 *  returns null for bare modifier presses. */
export function eventToCombo(e: Pick<KeyboardEvent,
  "key" | "ctrlKey" | "metaKey" | "altKey" | "shiftKey">): string | null;

export function matchKeybind(e: KeyboardEvent): KeybindId | null;
```

Details: `Enter` (from `e.key === "Enter"`), `Delete` (Cockatrice calls it Del), letters uppercased, `=`/`-` literal keys. One combo per action; `matchKeybind` is pure so the tests cover everything without DOM rendering. Vitest cases: Ctrl+D vs ⌘+D equivalence, Alt+F ≠ plain F, `event.repeat` handled by caller, `Ctrl+Delete`/`Ctrl+Alt+T`/`F3`/`Shift+Enter` parsing, bare modifiers → null.

## 3. Arrow gesture: Ctrl+right-click → sticky click-to-place (GameTable.tsx)

Reuse the **existing** "Draw arrow to…" picking mode — it already does cursor-following with no button held, left-click-commits-on-valid-target, Esc/banner cancel. Changes:

1. **`onCardPointerDown` (`GameTable.tsx:204`)**, `button === 2` branch: if `event.ctrlKey || event.metaKey` **and** `onAnyBattlefield(view, card.uid)` → `setArrowPicking(card)` + `setArrowDraft({fromUid, x: event.clientX, y: event.clientY})` for instant feedback + set a sync `suppressMenuRef.current = true`; return. Non-ctrl right-press: no longer arms anything.
2. **Delete the right-drag arrow machinery**: `pendingArrow` ref (line 200), `PendingArrow` type (57-64), the whole right-drag effect (389-426) and `commitArrow`-on-release path. `DRAG_THRESHOLD_PX` stays (left-drag still uses it).
3. **`onCardContextMenu` (358-368)**: battlefield right-clicks now open the menu directly here (same as hand cards) — `if (arrowPicking || arrowDraft || suppressMenuRef.current) return;` then `openCardMenu(card, …)`; clear `suppressMenuRef`. This also fixes the pre-existing gap where right-click during picking opened the menu.
4. Picking effect (430-456) unchanged: releases of the right button are ignored (`onUp` checks `button !== 0`), left-click on a card/player head commits `DRAW_ARROW`, click elsewhere/Esc cancels, banner + highlight rings + `ArrowDraft` rubber band all keep working (agent-verified: geometry needs zero changes — `arrowPath` already takes arbitrary points).
5. Polish: `cursor-crosshair` class on the table container while `arrowPicking`; update the header hint at 910-913 ("right-drag to draw an arrow" → "Ctrl+right-click a card to draw an arrow"); `Alt+A` and the menu's "Draw arrow to…" feed the same mode.
6. **AGENTS.md**: update the arrows bullet ("Drawn by right-drag…" → Ctrl+right-click / menu / Alt+A, placed by left-click) and add a short keybinds note.

## 4. Hover plumbing for hovered-card binds

`onCardHover` currently carries only `CardDef` (zoom) — extend to `(def: CardDef | null, card: CardView | null) => void` in `CardSprite.tsx:24,70-72`, threaded through `PlayerBand.tsx` and `HandFan.tsx` (signature-only). GameTable keeps `zoom` as-is and adds `const [hoverCard, setHoverCard] = useState<CardView | null>(null)` via one wrapper `onHover(def, card) { setZoom(def); setHoverCard(card); }` passed at the three `onCardHover={…}` sites (943/986/1025). Hovered-card binds resolve via existing `findOwnCard(view, you, hoverCard.uid)` and no-op when null/not-own. (Previews already persist across the zoom-panel hover path — unchanged.)

## 5. Keybind dispatch effect (GameTable.tsx)

One new `useEffect` with a `window.addEventListener("keydown")`, following the existing Escape-effect pattern (611-652) but stricter:

- **Guard**: `event.repeat` → return; target is `INPUT`/`TEXTAREA`/`[contenteditable]` → return (chat box, pile filter, token search, count picker, life editor).
- `matchKeybind(event)` → `preventDefault()` (blocks bookmark/save/find/refresh defaults) → switch on `KeybindId` calling existing helpers: `send`, `setPicker`, `setPile`, `setTokenOpen`, `closePile`-adjacent flows, `addNote(hoverCard)`, `setArrowPicking(hoverCard)`, select-all via `setSelected(new Set(hand.map(c => c.uid)))` + `setSelectMode(true)`.
- Life/chat focus: ChatPanel gets `chatFocusTick`/`lifeFocusTick` number props. ChatInput focuses its input in an effect on tick change (focus only — no setState, so `react-hooks/set-state-in-effect` stays clean). The life editor uses a render-time state reset in `PlayerRow` (`if (tick !== seen) { setSeen(tick); setEditing(true); setValue(String(player.life)); }` — the AGENTS-sanctioned pattern) and relies on the input's existing `autoFocus`.
- "Create another token": `TokenModal`'s create callback also records `lastToken` state in GameTable; `Ctrl+G` resends it (disabled until one exists).

## 7. Acceptance criteria

1. Every bind in §1 fires its action from a plain page (two-tab e2e sanity: keys work for the seated player whose tab has focus).
2. Binds are inert while typing in any input (chat, pile filter, token search, count picker) — typing "d" in chat never draws.
3. `preventDefault` holds: Ctrl+D/S/R/B/L/A, F3/F4, Alt-keys never trigger bookmark/save/refresh/sidebar/find.
4. Arrow: Ctrl+right-click a battlefield card → arrow appears and follows the cursor after button release; left-click a card/player head commits `DRAW_ARROW`; Esc/click-on-empty cancels; plain right-click **and** plain right-drag now open the card menu; hand cards behave exactly as before; right-click during picking never opens the menu.
5. `npm test` green including new `keybinds.test.ts`; `npx tsc --noEmit` and `npx eslint src` clean in `frontend/`; existing `arrowGeometry` tests untouched and passing; `server/scripts/e2e-m2.js` unaffected (no protocol change).
