# Corner-table battlefield + board focus views

**Frontend-only.** The wire contract already stores battlefield `x/y` as percentages of the owning player's board (owner's frame, card center), and all mirroring is client-side — so `shared/` and `server/` are untouched. No new actions, no cardCache version bump (`CardDef` already carries both `small` and `normal` URLs).

Decisions incorporated: duel view is **stacked** (opponent top, you bottom — i.e. the 2-player geometry); fullscreen = **in-place battlefield-area swap by default, plus a Maximize button** for a true fullscreen overlay; opponent boards stay **point-mirrored** `(100−x, 100−y)` with upright art.

## 1. Seat geometry (table mode, every player count)

One algorithm in a pure function — you always occupy the bottom row; opponents fill the rest in join order:

| Players | Grid | Arrangement |
|---|---|---|
| 2 | 1 col × 2 rows | opponent top (full width), you bottom — identical to today |
| 3 | 2 cols × 2 rows | both opponents top, **you span the full bottom row** |
| 4 | 2 cols × 2 rows | four quadrants ("4 corners"), you bottom-right |
| 5 | 3 cols × 2 rows | 3 opponents top, 1 opponent + you spanning 2 bottom |
| 6 | 3 cols × 2 rows | 3 opponents top, 2 opponents + you bottom |

`cols = max(1, ceil(N/2))`; top row = first `cols` opponents left→right; bottom row = remaining opponents left→right, then you spanning leftover columns. Your own board gets priority space (bigger when you're alone in the bottom row).

### `tableLayout.ts` (new)

```ts
export type FocusMode =
  | { kind: "board"; playerId: PlayerId }   // one board, battlefield-area swap
  | { kind: "duel";  opponentId: PlayerId } // you vs one opponent, stacked

export type Seat = {
  player: PlayerView;
  row: 0 | 1;
  col: number;      // 0-based
  colSpan: number;  // >1 when a board spans leftover columns
};

export function seatGrid(players: PlayerView[], you: PlayerId | null):
  { cols: number; rows: 1 | 2; seats: Seat[] };
// every player placed exactly once; you is always the last bottom-row seat

// card width tiers (px) shared by Battlefield and the drag ghost
export const CARD_W = { table: 90, duel: 130, board: 190, boardMax: 260 } as const;
export function cardWidthFor(focus: FocusMode | null, maximized: boolean): number;
export function imageFor(width: number): "small" | "normal"; // normal when ≥150
```

### `Battlefield.tsx` (rewrite as orchestrator)

- Receives new props: `focus: FocusMode | null`, `onFocus(pid)`, `onDuel(pid)`, `onExitFocus()`, `onToggleMaximize()`, `maximized: boolean` (plus existing props; `battlefieldRef` now targets your own band's board container).
- **Render-time validity guard** (no effects, per the `set-state-in-effect` eslint error): `const f = focus && players.some(p => p.id === focus.playerId) ? focus : null` — a focused player leaving/kicked falls back to table view automatically.
- **Table mode:** outer container keeps `data-drop="battlefield"`, rounded border, gradient; inside, a CSS grid `gridTemplateColumns: repeat(cols, minmax(0,1fr))`, `gridTemplateRows: rows === 2 ? "1fr 1fr" : "1fr"`, small gap, zinc cell borders. One `PlayerBand` per seat (`gridRow`/`gridColumn`/span). Cards at 90px / `small`.
- **Duel mode:** 2-row grid — opponent top (mirrored), you bottom. Cards at 130px / `small`.
- **Board mode:** single `PlayerBand` filling the area (yours: drops live; opponent's: mirrored, view-only). Cards at 190px / `normal`.
- **Mode bar** (focus modes only, slim strip above the grid): context label ("Kai's board" / "You vs Kai"), Maximize/Minimize button, ✕ back-to-table.

### `GameTable.tsx` (modify)

- New state: `focus: FocusMode | null`, `maximized: boolean` (both reset by Esc in level order: maximized → focus → existing overlays menu/pile/token/zoom).
- When `maximized && focus`, the Battlefield renders inside a `fixed inset-0 z-40` overlay (same component, `boardMax` width tier) instead of the center column; HandFan/ZoneRail/ChatPanel stay mounted underneath.
- **`finishDrag` battlefield branch simplifies** — delete the `bandCount`/`bandTop` math (`GameTable.tsx:150-156`) and measure your own board directly:
  ```ts
  const rect = battlefieldRef.current.getBoundingClientRect(); // your band, any mode
  const px = ((x - rect.left) / rect.width) * 100;
  const py = ((y - rect.top) / rect.height) * 100;
  ```
  Keep the existing clamps `x: 4–96, y: 8–92` and `MOVE_CARD`-then-`SET_POSITION` ordering. Outer container still carries `data-drop="battlefield"`, so releasing over any part of the battlefield area clamps into your board (same forgiveness as today). If your board isn't rendered (viewing an opponent's board), `battlefieldRef.current` is null → drop no-ops. Attach-on-drop (`data-card-uid`) is untouched and still works in every mode.
- **Drag ghost** derives its size/offset from `cardWidthFor(focus, maximized)` (replacing hardcoded `-45/-63` and the fixed 90px width) so the ghost matches your board's current card size; use `normal` image when width ≥ 150.
- 2-player games keep today's exact geometry, so the drop-math change is behavior-identical there (regression checkpoint).

## 5. Acceptance criteria

1. 2P: visually and behaviorally identical to today (drops land at release point, opponent band mirrored).
2. 4P: 2×2 quadrants on every screen, each viewer's own board bottom-row; same drop renders consistently (mirrored) on all other viewers — verified with 2+ tabs.
3. 3P/5P/6P: your board spans/anchors the bottom row per the table above.
4. Every band header has expand; swords on opponents opens duel; Maximize toggles the true-fullscreen overlay; Esc backs out one level at a time; focusing a player who then leaves auto-returns to table.
5. In board-focus-on-yourself and duel modes you can still drag from hand onto your board; tap/attach/context menu/hover-zoom/counters unchanged in all modes.
6. `npm test` green (new tests included), `npx tsc --noEmit` clean in `frontend/` and `server/`, `npx eslint src` clean, `node server/scripts/e2e-m2.js` passes (protocol untouched).
