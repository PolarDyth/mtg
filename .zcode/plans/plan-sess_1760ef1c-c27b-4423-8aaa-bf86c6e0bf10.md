## The 9 items (deduped — hand size was reported twice)

**§2 Show opponents' hand size** — Data already arrives: opponents' `hand`/`library` are `{kind:"count"}` in every snapshot (`server/src/engine/view.ts:17,40-49`); nothing renders it. Frontend-only: add Hand + Library count chips to `PlayerBand.tsx` header (next to the existing GY/exile/command `PILE_CHIPS`, lines 10-14, 119-137) and a hand count to `ChatPanel.tsx` player rows (88-189). Acceptance: every opponent band + player-list row shows live hand count; updates on draw/discard/mulligan.

**§3 Theme card names in the deck loader** — Root cause verified: "The Dead Marshes" is the **flavor name** of the LTC printing of Urborg, Tomb of Yawgmoth; `resolveCards` matches only canonical/front-face names (`frontend/src/lib/scryfall.ts:110-118`), and autocomplete wouldn't help (only suggests "Haunt of the Dead Marshes"). Steps: add `flavor_name` to `ScryfallCard`; match inputs against it too; for names still missing after the batch pass, fall back to `GET /cards/named?fuzzy=` (capped ~20 names, ~100ms apart — same rate-limit posture as batching); extract the input→card matching into a pure function and add vitest cases (flavor name, front face, accented canonical). Acceptance: pasting "1 The Dead Marshes" resolves to Urborg with image; genuine typos resolve via fuzzy; unresolvable names still flagged in review UI.

**§4 Missing token emblems** — `searchTokenCards` queries `t:token <name>` (`scryfall.ts:157-166`); emblems are `t:emblem` so they never appear. Change query to `(t:token or t:emblem) <name>`. Acceptance: searching "Jace" finds Jace emblems; spawnable with image + count.

**§5 Right-click a card → spawn its tokens (X-aware)** — No `all_parts` usage anywhere today. Steps: extend `CardDef` with `relatedTokens: {id, name}[]` captured in `toDef` from `all_parts` (component `token`, or type_line Token/Emblem); **bump cardCache version** (`mtg:cards:vN`, AGENTS.md rule); new "Create token…" submenu in `ContextMenu.tsx` for battlefield cards listing related tokens (thumbnails lazily resolved via existing `resolveCardsByIds`); pick → `CountPickerModal` (1–20, the X) → existing `CREATE_TOKEN {name, cardId, count}` (`server cards.ts:140-179` — zero server changes; >20 via Ctrl+G repeat). Acceptance: right-clicking a card that makes tokens offers them with art; quantity honors X.

**§6 Clone cards** — Frontend-only: "Clone" menu item on face-up battlefield cards sends `CREATE_TOKEN {name: cardName, cardId: card.cardId, count}` (works on opponents' cards too — battlefield cardIds are public; hidden for face-down → hide the item there). Acceptance: clone appears on battlefield with same art, untapped, count honored.

**§7 No more auto-attach on drop** — Root cause: `GameTable.finishDrag` hit-tests `document.elementFromPoint` and silently sends `ATTACH_CARD` when released over any card (`GameTable.tsx:253-260`). Steps: delete that branch (drops always position); make `SET_POSITION` clear `attachedTo` server-side (dragging away = detach; keep the existing Detach menu item); add explicit **"Attach to…"** card-menu mode mirroring the existing "Draw arrow to…" targeting flow (pick source → click target card). Server test: SET_POSITION on an attached follower detaches. Acceptance: dropping onto a card never attaches; attaching only happens via the explicit flow.

**§8 Fix counters** — Reported: each +1 requires closing/reopening the menu, the editor's numbers go stale, and multiple counter kinds render as one number. Root cause: `CounterEditor` lives inside the transient `ContextMenu` (`ContextMenu.tsx:319-366`) with no optimistic local state — every bump waits on a full snapshot round-trip — and `CounterBadge` shows only the sum + `★` (`CardSprite.tsx:30-43`). Steps: promote counters to a dedicated persistent popover (anchored to the card, stays open, local state synced on snapshot, direct value input per kind, preset chips +1/+1 · −1/−1 · lore · shield · stun, remove-kind button); replace the single-sum badge with per-kind chip badges on the sprite. Engine already supports all of this (`Record<string, number>`, 0–999). Acceptance: click + five times in a row in one open editor; set loyalty to 6 in one edit; a card with +1/+1×3 and lore×2 shows both kinds distinctly.

**§9 Easy game start** — Three parts. (a) **Auto-draw**: `START_GAME` draws 7 for each player with a non-empty library (`server game.ts:20-45`; deterministic splice, no rng) + system chat line. (b) **Ready checks**: lobby shows "N/M decks loaded"; Start stays clickable but confirms with a list of deckless players (warn, never block — matches the structural-only philosophy). (c) **Mulligan with player-chosen draw count** (user's explicit variant, not London): new action `MULLIGAN { draw: number }` — shared union entry, handler in `game.ts` (requireStarted; hand → library, shuffle via ctx.rng, draw `min(draw, library)`; integer 0–99), system chat "Ada mulligans to N"; "Mulligan…" button in the hand Actions dock opening `CountPickerModal` (default = current hand size). Tests in `actions/game.test.ts` via `startWithDeck` harness. Acceptance: start → everyone has 7 without manual draws; mulligan to any chosen N; e2e updated.

**§10 Turn phases (labels + conveniences)** — New shared `Phase` union (untap · upkeep · draw · main1 · startCombat · attackers · blockers · damage · endCombat · main2 · end) + `Game.phase` (default `"untap"` on START_GAME) + `GameView.phase` + one action `SET_PHASE {phase}` (requireStarted, member check only). Convenience (user-chosen): `NEXT_TURN` additionally untaps the incoming player's battlefield cards (still clears arrows as today). UI: `PhaseBar` — clickable strip centered between boards, active phase highlighted, "Next ▸" advances (client computes: within-turn → `SET_PHASE`, from `end` → `NEXT_TURN`); repoint Ctrl+Enter to next-phase-or-turn. Server stays dumb (no gating on active player, no per-phase automation beyond the untap). Tests: SET_PHASE validation, NEXT_TURN untap + phase reset, view exposure. Acceptance: strip syncs for all players in 2 tabs; passing turn untaps the new active player; no rules are enforced.
