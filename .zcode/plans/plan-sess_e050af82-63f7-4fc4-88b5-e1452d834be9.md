## Phase 2 — §3 Flavor names + fuzzy fallback in the deck loader

All in `frontend/src/lib/scryfall.ts` unless noted:

1. `ScryfallCard` type: add `flavor_name?: string` (collection responses include it).
2. New exported pure matcher (unit-testable, no network):
   ```ts
   function normalizeForMatch(s: string): string {
     return s.normalize("NFD").replace(/\p{Diacritic}/gu, "").toLowerCase().replace(/\s+/g, " ").trim();
   }
   export function cardNameMatches(input: string, card: { name: string; flavor_name?: string }): boolean
   ```
   True when normalized input equals the canonical name, the front face (`name.split(" // ")[0]`), or the flavor name. (Normalization adds case/whitespace/accent tolerance — e.g. "Lim-Dul" vs "Lim-Dûl".)
3. `resolveCards` (lines 105–119): replace the inline canonical compare with `cardNameMatches(input, raw)` (must use the raw card, not the def, for `flavor_name`); delete the dead `foundNames` set.
4. Fuzzy fallback after the batch loop: `ResolveResult` gains `fuzzy: string[]`. For up to 20 still-missing names, ~100 ms apart, `GET /cards/named?fuzzy=<encoded>`; 200 → `toDef` → `defs.set(name, def)` + record in `fuzzy`; 404/network error → stays missing. Return `missing: missing.filter(n => !defs.has(n))`.
5. `frontend/src/components/game/DeckLoader.tsx`: store `result.fuzzy` as a `Set<string>`; in `BoardList` rows add a subtle amber "search" tag + `title="matched via Scryfall fuzzy search — check it's the right card"` when `fuzzy.has(line.name)`, so wrong fuzzy hits are visible before loading.
6. **Tests** — new `frontend/src/lib/scryfall.test.ts` (vitest, colocated like `decklist.test.ts`): canonical match, case-insensitive, whitespace-collapsed, front-face ("wear" → "Wear // Tear"), flavor name ("the dead marshes" → `{name:"Urborg, Tomb of Yawgmoth", flavor_name:"The Dead Marshes"}`), accented canonical, non-match.
