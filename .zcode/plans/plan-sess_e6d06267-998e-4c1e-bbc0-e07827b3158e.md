# Docker + Compose for Mythic Table (production, Linux)

Zero application-code changes. The image runs **exactly what `npm start` runs** (`node --import tsx server/src/index.ts` from the repo root) because of the documented constraint: compiled CJS can't require the raw-TS `@mythic/shared` package.

## Constraints the design honors (discovered during exploration)

- `next.config.ts` has **no `output: 'standalone'`** and the custom server boots `next({ dev, dir: <repo>/frontend })` with `frontendDir = path.resolve(__dirname, "../../frontend")` — so the runtime image must ship the **exact workspace layout** (root-hoisted `node_modules`, `frontend/{.next,public,configs,src}`, `server/`, `shared/`).
- `tsx`, `next`, `ws` are **production** deps of `server` → `npm ci --omit=dev` yields a lean runtime with no package.json edits.
- `server.listen(port)` passes no host → binds all interfaces; `NODE_ENV=production` is the only env the server needs. No code changes required for Docker.
- `npm run build` = `next build` **+ `tsc --noEmit` on server**, and server's tsconfig `include: ["src"]` **includes `*.test.ts`** → tests MUST stay in the Docker context (the build doubles as a typecheck gate).
- No fs writes at runtime (games are RAM-only) → safe to run as non-root `node` user.

## 1. `Dockerfile` (full content)

```dockerfile
# syntax=docker/dockerfile:1
ARG NODE_VERSION=22

# --- deps: all deps (dev deps are needed for next build + typecheck) ---
FROM node:${NODE_VERSION}-alpine AS deps
WORKDIR /app
COPY package.json package-lock.json ./
COPY frontend/package.json frontend/
COPY server/package.json server/
COPY shared/package.json shared/
RUN npm ci

# --- build: next build + server tsc --noEmit (typecheck gate) ---
FROM deps AS build
ENV NEXT_TELEMETRY_DISABLED=1
COPY shared/ shared/
COPY frontend/ frontend/
COPY server/ server/
# cache/ is only useful for incremental rebuilds; drop it from the image
RUN npm run build && rm -rf frontend/.next/cache

# --- prod-deps: runtime-only node_modules (tsx/next/ws are prod deps) ---
FROM node:${NODE_VERSION}-alpine AS prod-deps
WORKDIR /app
COPY package.json package-lock.json ./
COPY frontend/package.json frontend/
COPY server/package.json server/
COPY shared/package.json shared/
RUN npm ci --omit=dev

# --- runtime: same command as `npm start`; shared/ is raw TS, keep layout ---
FROM node:${NODE_VERSION}-alpine AS runtime
ENV NODE_ENV=production \
    PORT=3000 \
    NEXT_TELEMETRY_DISABLED=1
WORKDIR /app
COPY --from=prod-deps --chown=node:node /app/node_modules node_modules
COPY --chown=node:node package.json package-lock.json ./
COPY --chown=node:node shared/ shared/
COPY --chown=node:node server/ server/
COPY --chown=node:node frontend/ frontend/
COPY --from=build --chown=node:node /app/frontend/.next frontend/.next
USER node
EXPOSE 3000
HEALTHCHECK --interval=30s --timeout=5s --start-period=15s --retries=3 \
  CMD wget -q --spider "http://127.0.0.1:${PORT}/" || exit 1
CMD ["node", "--import", "tsx", "server/src/index.ts"]
```

Notes:
- Manifest-only copies before `npm ci` keep the dependency layer cached across source edits.
- `COPY frontend/ frontend/` in runtime copies source/configs/public from the context (`.next` and `node_modules` stripped by `.dockerignore`), then the built `.next` is overlaid from the build stage.
- npm's workspace symlinks (`node_modules/@mythic/shared` → `/app/shared`) survive `COPY --from` and resolve once `shared/` is copied in.
- Healthcheck uses busybox `wget` (present on alpine); `${PORT}` expands at runtime via shell-form CMD.

## 2. `docker-compose.yml`

```yaml
services:
  mythic-table:
    build: .
    image: mythic-table:latest
    container_name: mythic-table
    init: true # tini as PID 1 -> clean SIGTERM handling
    restart: unless-stopped
    ports:
      - "${MYTHIC_PORT:-3000}:3000"
```

Host port override via `MYTHIC_PORT=8080 docker compose up -d --build` or a `.env` file (compose reads `.env` for substitution; `.dockerignore`'s `.env*` only affects the build context, so that's not a conflict).

## Acceptance criteria (run in order)

1. `docker compose build` succeeds — gates on `next build` + server `tsc --noEmit`.
2. `docker compose up -d` then `curl -f http://localhost:3000/` returns 200 HTML.
3. `docker compose ps` shows `healthy` within ~45s.
4. `node server/scripts/e2e-m2.js` from the repo root (host) passes — proves `/ws` upgrade + full protocol work inside the container.
5. `docker exec mythic-table id -u` → `1000` (non-root).
6. `MYTHIC_PORT=8080 docker compose up -d` serves on 8080.
7. `docker compose stop` exits promptly (no 10s SIGKILL grace timeout).

## Caveats / notes

- Runtime image lands ~400–500MB (Next isn't standalone; custom server requires full `node_modules`). Accepted trade-off vs. the standalone-output refactor, which the AGENTS.md gotcha warns against.
- If a native dep ever misbehaves on alpine/musl, switch the three `FROM node:${NODE_VERSION}-alpine` lines to `22-slim` — single-tag fix (all deps ship prebuilt binaries; no compilation happens in-image).
- arm64 Linux hosts: build on the host with the same commands (node base image is multi-arch); cross-building from Windows for an arm64 server needs `docker buildx --platform linux/arm64`.
- Windows Docker Desktop builds this identically; the image itself is Linux.
