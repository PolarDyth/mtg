# Mythic Table — Implementation Plan (rev 2, detailed)

Build a Cockatrice-style MTG virtual tabletop per the design doc, with the review decisions folded in: split `frontend/` + `server/` + `shared/` workspace layout (single process, one port), v1 action set extended with tokens, reveal, sideboard zone, and attachments; only the card's owner may act on it; token-based rejoin.

## 0. Verified technical foundation

- Next 16 custom server API confirmed in `frontend/node_modules/next/dist/docs/01-app/02-guides/custom-server.md`: `next({ dev, dir })` boots a Next app located at another path; `app.prepare()`, `app.getRequestHandler()` as usual.
- `app.getUpgradeHandler(): (req, socket, head) => Promise<void>` exists in `next/dist/server/next.d.ts` — upgrade routing pattern: `server.on('upgrade')` → if `pathname === '/ws'` hand to `ws`, else forward to Next's upgrade handler (keeps dev HMR socket alive). Turbopack is the default bundler and works through custom servers; fallback option `webpack: true` if HMR misbehaves (prod unaffected).

## 2. Shared types (`shared/src/index.ts`)

```ts
type Zone = 'library'|'hand'|'battlefield'|'graveyard'|'exile'|'command'|'sideboard';

type CardInstance = {
  uid: string; cardId: string | null;   // null in views = hidden from you
  x: number; y: number;                 // battlefield %, 0–100
  tapped: boolean; faceDown: boolean;
  counters: Record<string, number>;
  annotations: string[];
  attachedTo?: string;                  // host CardInstance uid
};

type Action =
  | { type:'LOAD_DECK'; library: DeckEntry[]; sideboard: DeckEntry[] }   // DeckEntry = {cardId, count}
  | { type:'START_GAME' }
  | { type:'DRAW_CARDS'; count:number }
  | { type:'MOVE_CARD'; uid:string; to:Zone; index?:number }
  | { type:'MOVE_CARD_INDEX'; uid:string; index:number }
  | { type:'SET_TAPPED'|'SET_FACE_DOWN'; uid:string; value:boolean }
  | { type:'SET_COUNTERS'; uid:string; counters:Record<string,number> }
  | { type:'SET_POSITION'; uid:string; x:number; y:number }              // sent on drag-end only
  | { type:'ATTACH_CARD'; uid:string; to:string|null }
  | { type:'CREATE_TOKEN'; name:string; cardId?:string; count:number }
  | { type:'REVEAL_CARDS'; uids:string[] }
  | { type:'SHUFFLE_LIBRARY' }
  | { type:'SET_LIFE'; life:number }
  | { type:'ROLL_DIE'; sides:4|6|8|10|12|20|100 }
  | { type:'NEXT_TURN' } | { type:'SEND_CHAT'; text:string } | { type:'LEAVE_GAME' };

// wire: client → server
type ClientMessage = { kind:'join'; code:string; name:string }
                   | { kind:'rejoin'; code:string; token:string }
                   | { type:'action'; action:Action };
// wire: server → client
type ServerMessage = { type:'welcome'; token:string; you:PlayerId }
                   | { type:'snapshot'; state:GameView }
                   | { type:'error'; message:string };

type ZoneView = { kind:'cards'; cards:CardInstance[] } | { kind:'count'; count:number };
type PlayerView = { id:PlayerId; name:string; life:number; connected:boolean;
                    started:boolean;
                    zones: Record<Zone, ZoneView> };
type ChatMessage = { id:string; at:number; playerId:PlayerId;
                   | kind:'text'; text:string | kind:'dice'; sides:number; result:number
                   | kind:'reveal'; cards:{name:string; cardId:string}[]
                   | kind:'system'; text:string };   // join/leave/turn/token/shuffle notices
type GameView = { code:string; started:boolean; activePlayerId:PlayerId;
                  players:PlayerView[]; chat:ChatMessage[] };  // chat capped at 200
```

## 3. Server engine (pure functions, injected RNG)

- `applyAction(game, action, actorId, rng)` returns `{ok:true, game}` or `{ok:false, error}`. Mutates a cloned state (or returns new). All side effects (uid minting, shuffling, dice) use the injected `rng` so vitest runs are deterministic.
- **Validation is structural + ownership**: uid exists, actor is seated, game started (except LOAD_DECK/START_GAME/LEAVE), and **the target card's owner is the actor** for every uid-addressed action. No game-rule checks, ever.
- **Ownership rules per action**: uid actions → owner only. `SHUFFLE_LIBRARY`, `DRAW_CARDS`, `SET_LIFE`, `LOAD_DECK`, `CREATE_TOKEN` → self. `ROLL_DIE`, `NEXT_TURN`, `SEND_CHAT`, `START_GAME` → any seated player (logged to chat as system messages).
- **Hidden info / `view.ts` personalization**: own `hand`/`library`/`sideboard` → full cards (own library order IS visible — that's what SHUFFLE is for); opponents' `hand`/`library`/`sideboard` → count only. `battlefield`/`graveyard`/`exile`/`command` → full for everyone, except face-down battlefield cards carry `cardId: null` for everyone but the owner. Attached cards inherit host visibility.
- `REVEAL_CARDS` (own cards only) appends a `reveal` chat message carrying resolved `{name, cardId}` pairs so every client can render images without having the data. `CREATE_TOKEN` mints instances directly into the actor's battlefield; when `cardId` is absent the client renders a labeled colored rectangle.
- `MOVE_CARD` cross-player zones: moving an opponent's card is rejected by ownership; "giving" a permanent is done by the owner dragging it (v1: cards stay owned by their mover).

## 4. Server runtime

- `index.ts`: `createServer()` → Next `handle`; `app.prepare()`; `server.listen(PORT||3000)`. `server.on('upgrade')`: `/ws` → `wss.handleUpgrade`, else → `app.getUpgradeHandler()` (HMR in dev). `dir` resolved relative to the server file so dev (tsx) and prod (dist) both find `../frontend`.
- `ws.ts`: parse first message as join/rejoin. Join on unknown code → create room (host = first player, cap 6). Rejoin with valid token → reattach seat, mark connected, send full snapshot. Send `welcome {token, you}` then `snapshot`. Every applied action → re-broadcast personalized snapshot to each connection. Heartbeat: ws ping every 30s, terminate after 2 missed; `connected` flag flows into views.
- `rooms.ts`: codes = `WORD-NUMBER` ("PLAINS-42") from a ~64-word list × 4 digits, regenerate on collision. GC: room deleted 1h after last connection closes. **Amendment to doc §9**: seats persist for the room's lifetime (no 5-min eviction — evicting a mid-game player with permanents out is worse than keeping the seat); the 5-min figure is dropped, token rejoin works any time the room lives.
- Nothing persists to disk; restart = rooms gone (acceptable v1, documented).

## 5. Frontend — connection & state

- `src/app/page.tsx`: name + "create room" / "join with code" form; stores `{name, token?}` in `sessionStorage['mtg:'+code]` (per-tab → two tabs = two players, which is exactly the two-browser-tab test setup); routes to `/game/[code]`.
- `useGame(code)` hook: opens `ws(s)://location.host/ws`; on open sends join or rejoin (if token in sessionStorage); stores token from `welcome`; reconnect with backoff 1s→2s→4s…max 10s; feeds `ServerMessage`s into a `useReducer` holding the latest `GameView`; exposes `send(action)`.
- Optimistic UI for exactly one thing: the in-flight drag position of the card being dragged; everything else waits for the authoritative snapshot.

## 6. Frontend — components (`src/components/game/`)

- `GameTable`: full-screen no-scroll grid — battlefield center, zone rail left of your area, hand bottom, chat right.
- `Battlefield`: one horizontal band per player (you at bottom, opponents stacked above); cards absolutely positioned at `(x%, y%)`.
- `CardSprite` (memoized): Scryfall `small` image (146×204, displayed ~90px wide); tap = CSS `rotate(90deg)`; counter badges (top-left, +click to edit); face-down = card-back; annotation pin; attached cards render at a fixed offset from host and move with it.
- `HandFan`: overlapping fan, hover raises + enlarges, drag out to battlefield (→ `MOVE_CARD` + `SET_POSITION` on drop).
- `ZonePile` ×5 (library / graveyard / exile / command / sideboard): pile with count badge; library click = draw 1, right-click = shuffle; other piles open `PileModal` (grid of contents, drag out).
- `ChatPanel`: log rendering text/dice/reveal/system messages; per-player life totals with ±n and set-exact input; dice buttons (d4/d6/d8/d10/d12/d20/d100); "Next turn" button highlighting the active player.
- `CardContextMenu` (custom right-click): tap/untap, face-down, counters editor, add note, attach/detach, reveal, clone→token.
- `TokenModal`: name search against Scryfall (`q=t:token <name>`), preview, count, fallback to unlabeled rectangle token.
- `ZoomPanel`: fixed corner panel showing `normal`-size image on hover/hold.
- `Lobby` (pre-start overlay): player list, `DeckLoaderModal`, host-ish "Start game".
- Drag & drop: Pointer Events with `setPointerCapture`; on pointerup hit-test drop targets — battlefield (convert to %), zone piles, own hand; `SET_POSITION` fires on drag-end only, never per-mousemove.

## 7. Frontend — Scryfall client (`src/lib/scryfall.ts`, `decklist.ts`, `cardCache.ts`)

- `parseDecklist(text)`: handles `4 Lightning Bolt`, `4x Name`, bare `Name`, `SB: 1 X`, `[SET] N Name`, blank/section headers ("Sideboard", "Maindeck"), Moxfield/Archidekt plain-text exports. Unknown lines → quantity 1 + flagged for review.
- `resolveCards(entries)`: `POST /cards/collection` (exact-name identifiers) in batches of 75, ~100ms between batches (good-faith rate limiting); returns resolved defs + list of missing names surfaced in the UI for manual fix.
- `cardCache.ts`: localStorage `mtg:cards:v1` mapping cardId → minimal def `{name, mana_cost, type_line, small, normal}` (~200 bytes/card — thousands fit in the 5MB quota). Versioned key; old versions evicted.

Single Node process (`node server/dist/index.js` after `next build` + `tsc`). `PORT` env respected. Targets: Railway / Fly.io / Render / VPS — not Vercel (no persistent WebSockets). No database, no disk persistence.

## 11. Risks & mitigations

- **Turbopack dev through custom server**: API verified; if HMR degrades, set `webpack: true` in the `next()` options (prod path unaffected).
- **Scryfall limits**: batched + spaced calls, aggressive localStorage caching, all image URLs hotlinked from their CDN.
- **Snapshot chattiness**: snapshots are a few KB; only per-action broadcasts (drag throttled to drop); 6-player cap keeps this trivial.
- **localStorage quota**: minimal card defs only, versioned cache.
